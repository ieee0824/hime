# Hime Review

himeでRustコードを構文解析し、副作用の兆候と判定できない箇所をレビューする。解析対象のコードは実行しない。

## 実行

ユーザーが指定したRustファイル・ディレクトリを対象にする。指定がなければ、現在のプロジェクトの`src`を対象にする。ワークスペース全体の検査を求められた場合は、関係する各クレートのソースを指定する。

PATH上の`hime`を優先する。見つからない場合は`~/.cargo/bin/hime`も確認する。どちらもなければ、確認できたhimeリポジトリを`cargo run --manifest-path /path/to/hime/Cargo.toml --locked -- --json -- /absolute/path/to/target/src`で実行できる。対象プロジェクトのCargo.tomlをhimeの実行に使わない。himeの所在が分からなければ、その不足を伝える。

```bash
hime --json -- /absolute/path/to/target/src
```

JSONをstdout、エラーやスキップ警告をstderrから読み、終了コードも確認する。パスの前に`--`を付け、オプションに見えるファイル名もパスとして扱う。

| 終了コード | 扱い |
| --- | --- |
| 0 | impureなし。通常モードではunknownも許容される。 |
| 1 | 解析は成功し、impureを検出した。`--strict`ではunknownも対象。JSONを捨てたり、ツールの実行失敗として再試行したりしない。 |
| 2 | 入力・構文・オプションのエラー、またはRustファイルなし。原因を確認し、解析できたかのように報告しない。 |

`--strict`は、ユーザーが判定不能も失敗にする検査やCI設定を求めた場合に使う。警告でスキップされた入力は、検査範囲から外れたことを明記する。

## 診断をレビューする

JSONの`file`、`function`、`line`、`status`、`diagnostics`を使う。各診断には`line`、1始まりの`column`、`code`、`message`、`status`がある。重要な診断は該当ソースを開いて確認し、ツールのラベルだけで不具合と断定しない。

- `impure`: I/O、時刻、環境、乱数、静的状態、可変参照、出力・panic系マクロなどの兆候。仕様上必要な副作用と、計算から分離できる副作用を文脈に沿って判断する。
- `unknown`: 未解決呼び出し、メソッド、型情報、属性、マクロ、unsafe、クロージャ、async、再帰などによる解析限界。副作用があるという証拠にはしない。
- `candidate`: 検出範囲では兆候なし。純粋性・参照透過性の証明とは呼ばない。`--strict`成功も証明にはならない。

`callee_effect`は呼び出し先からの状態伝播。原因の関数と呼び出し元への影響を説明し、同じ原因を独立した不具合として重複列挙しない。

名前解決は同一ファイル内の関数・インラインモジュール・ブロック・useに限定される。複数ファイル、依存クレート、型検査、マクロ展開、cfgの実際の選択は解決しない。演算子のオーバーロード、暗黙のDrop、内部可変性、整数オーバーフロー、終了性も一般には分からない。既知の関数・マクロ・静的変数の名前による照合には誤検出があり得る。

## 結果と改善

検査範囲と各状態の件数を短く示し、重要な箇所をファイル・行・関数・根拠とともに報告する。確認できた問題と解析上の不確実性を区別する。結果がない場合も、検査対象に関数がなかったのか、全関数がcandidateだったのかを区別する。

改善を求められた場合は、必要なI/Oを境界へ寄せる、時刻や乱数を入力として渡す、可変参照で更新する代わりに値を返す、などを既存の仕様に合わせて検討する。ラベルを消すためだけに出力・panic・入力検証・公開APIを削除しない。レビューの依頼だけならソースを編集しない。

実装変更後は該当範囲を再解析し、変更に必要なテストを実行する。依頼されたRustコードの検査・改善という範囲を保ち、Issueの投稿やPRの作成を自動的に追加しない。
